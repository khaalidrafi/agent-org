* How to use this file

Every unit of AI-written code that is hard to review or easy to get wrong gets a
TODO here, with the file, the function and the one question to answer.  Done
means you read the code and agree it is right, not that the tests passed.

* Sync the transcript file on demand (added 2026-10-07)

User order: "Add option to sync transcript files based on latest features."
A mirror written only at turn boundaries goes stale when you upgrade: the buffer
shows the newest rendering but the file keeps the shape it was written in.  The
new command forces that mirror to catch up without a new prompt.

** TODO Read the =force= arg on =agent-org-buffer-transcribe= (agent-org-buffer.el)

The one design decision worth a second pair of eyes: FORCE skips exactly the two
guards that exist to /save a write/ (the =--transcript-cache= equality and the
lite-mode gate) and NOTHING else — it still honours =agent-org-transcribe= nil
and a session with no id.  Check the two =when= conditions read as intended, and
that the default =nil= leaves all nine existing boundary call sites on the old
behaviour.  Is overriding lite mode here right, or should a lite session's sync
still defer until the queue drains (the §14 rule)?  I chose to override it: a
deliberate "catch up now" is not a hot path, and the lite gate only ever exists
to save the 3–15 ms write a boundary was about to make anyway.

** TODO Confirm the re-mirror / re-render distinction holds in the docs

The command regenerates the metadata block and re-mirrors the body; it does NOT
re-render an exchange the running build never painted.  Read the command
docstring, README.org §"Transcript file" and CONVENTIONS §14 and confirm none of
them implies that syncing an old chat upgrades its old turns — the honest path
for that is resume-then-sync.  This is where a future reader could be misled, so
it is the line to police.

* Starting with the directory's older sessions (=agent-org-session-strategy=)

** TODO Read =agent-org-start= and =agent-org--begin-start= (agent-org.el)

The strategy is read once, in the command, and then travels with the session
through both callbacks that need it.  Question: agree that no callback should
ever read ~agent-org-session-strategy~ itself.  This was found live, not
theoretical: a probe that wrapped ~agent-org-start~ in
~(let ((agent-org-session-strategy 'new)) ...)~ still sent ~session/list~,
because ~initialize~ answered after the ~let~ had exited and the callback read
the global value.  The same trap already governed ~current-prefix-arg~, which
is why ~agent-org-start~ captured ~forced~ early; the bug was that the strategy
was not treated the same way.

** TODO Read the default flip and the two prefix tiers (agent-org.el)

~agent-org-session-strategy~ now defaults to ~latest~ — start a chat and the
directory's most recently updated session reopens, asking nothing.  The prefix
args are ordered by how much they hand back: one ~C-u~ is ~prompt~ (the chooser
this default used to be, with ~New session~ still first, so ~C-u RET~ is the old
plain start) and ~C-u C-u~ is ~new~.  Question: is ~latest~ the right default for
/how you/ work — if you often start a /second/ chat in a busy directory, this
changes your ~M-x agent-org-start~ from a chooser into a resume, and the muscle
memory is ~C-u~.

Two things to check in the code, both cheap and both easy to get wrong:

- the mapping is ~>= 16~ for ~new~, the same reading
  ~agent-org-resume-session~ already uses for its second tier, so one gesture
  means one thing across both commands;
- the tests that exercise ~prompt~ now /bind/ it explicitly.  They used to
  inherit it from the default, which is why five of them went red on a green
  build.  Binding it in the same ~let~ as the ~agent-org-start~ call does
  /nothing/: in ~let~ the value forms are evaluated before any of its variables
  is bound, so ~agent-org-start~ reads the global default — the strategy needs an
  /enclosing/ ~let~ (or ~let*~ with the strategy first).  That is the same
  "read it when the command runs" rule above, arriving from the test side.

** TODO Read =agent-org--settle-listing= and the registry's =:list-state=

One listing, exactly one outcome: whoever settles first — answer, failure or
the timeout — acts, and whoever arrives after is ignored.  Without it a goose
that answered 30 s late would load a second session into a buffer that had
already opened a fresh one.  Question: is leaving the value at ~settled~ right
(never back to ~nil~), and do you agree that
~agent-org--resume-locate~ needs no such guard because it arms no timer?

title is the only column a human reads.  Padding happens before
=propertize=, so the spaces belong to the dimmed column — which is why
the id is NOT padded: a padded tail would be trailing whitespace in the

** DONE Columns are measured in display width, not characters

=test-agent-org-candidate-columns-align-by-display-width= is what would
