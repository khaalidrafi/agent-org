* MiniMax through OpenCode

** TODO Read =agent-org--apply-pinned-model= (agent-org.el)

Question: is clearing ~:want-model~ *before* the request goes out the right
way to make the pin exactly-once?

It has to be: ~agent-org--session-ready~ runs again on every mid-turn
~session_info_update~, and a pin that re-sends each time is a wasted round trip
to a process that takes seconds to answer.  The cost is that a failed
~session/set_config_option~ is never retried in the same session — the follow-up
is ~C-c C-m~.

** TODO Read the ~:model~ key contract (agent-org-providers.el)

Provider plists now carry an optional ~:model~.  Question: should the pinned
MiniMax id be a defcustom instead of a literal in the default value of
~agent-org-providers~?  A literal is one less variable and ~customize-variable
agent-org-providers~ reaches it; a defcustom would be easier to document.

* Latent bugs this surfaced

** TODO Read =agent-org--failure-text= (agent-org.el) and its six call sites

~acp-send-request~ gives an ~:on-failure~ callback the whole response message
(~(:object …) (:json …)~).  Every failure path used to interpolate that into
the status, so a live opencode billing error replaced the header line's status
segment with hundreds of characters.  Question: any ~msg~ left un-routed?  grep
for =(format "… failed: %s" msg)=.

** TODO Read =agent-org-buffer--status-segment= (agent-org-buffer.el)

~starting~ and ~ready~ render the *state label*, never the ~:message~.  So
~:message~ alone is invisible while Ready — which is why a refused model pin goes
to the echo area and a real failure sets ~:state 'error~.  Recorded in
CONVENTIONS.md §6; check the wording there matches the code.
