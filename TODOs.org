#+title: agent-org TODOs --- features to port, inspired by agent-shell
#+options: num:t toc:nil

This is the porting list from `agent-shell' (upstream xenodium/agent-shell,
source at ~/agent-shell) onto agent-org's Org-native design.  Each item
names the agent-shell mechanism it comes from and the agent-org functions
it touches.  Everything marked DONE is on this branch with tests in
tests/test-agent-org.el.

* Basic chat-loop features (this round)
** DONE Prompt queue --- submit while the agent is still responding
agent-shell keeps this in =agent-shell-prompt-queue.el=: the queue lives
in the session state under =:pending-prompts=; =agent-shell--prompt-queue-enqueue=
stores a prompt typed while busy, and =--process-next= auto-drains it
when the turn ends.  Commands: =agent-shell-prompt-queue= (view),
=-resume=, =-remove=; a defcustom picks the busy-submit policy
(queue vs error).

Ported to agent-org as:
- Session key =:pending-prompts= (FIFO list of strings).
- =agent-org-send= enqueues instead of signalling "Agent is still
  responding" while =:streaming=; option =agent-org-queue-when-busy=
  keeps the old hard-error behaviour when nil.
- Drain only on a *successful* turn end (=agent-org--drain-queue= called
  from the send success callback); a failed turn leaves the queue intact
  so nothing hammers a dead agent.
- =agent-org-queue-view= (transient listing), =agent-org-queue-remove=
  (drop one, completion), =agent-org-queue-edit= (pull the last queued
  prompt back into the minibuffer prompt read).
- Header status shows the pending count while busy (convention: header
  line only, never the body, never the mode line).

*** DONE Queue input comes from the buffer, not the minibuffer
The first port read queue input with =read-string=, because sending froze
the live =* User= heading and left nowhere to type mid-turn.  That is not
agent-shell's model: =agent-shell-persistent-prompt-enabled= keeps a
writable prompt at the buffer end /through/ the turn, so queueing is just
submitting into a busy shell.

Ported as the persistent type-ahead box:
- =agent-org-buffer-insert-prompt= opens one =* User= box and sending
  never consumes it; every turn boundary can call it and the open box
  makes it a no-op.
- =agent-org-buffer--prompt-anchor=: a rear-advancing marker at the box's
  leading separator.  Rear-advancing is the whole trick -- text inserted
  at the anchor position pushes the marker (and the box) down, so renders
  keep arriving above it in order instead of stacking in reverse.
- =agent-org-buffer--render-end=: anchor position, or =point-max= when no
  box exists (a replay).  Every per-turn render site -- user echo, agent
  heading, chunks, tool headings, :thinking: drawer -- inserts there
  instead of =point-max=, so a streaming response never scribbles over a
  fresh draft.
- =agent-org-buffer-take-draft= replaces =agent-org-buffer-read-prompt=:
  read + clear the box, keep it open; a blank draft errors and leaves the
  typed text in place.
- =agent-org-send= is now one gesture: idle sends the draft (frozen echo
  above the box, turn on the wire), streaming queues it.  No minibuffer
  for new prompts; =agent-org-queue-edit= still uses one (the entry has
  left the input area).
- Drained prompts render as frozen echoes above the box, and a draft
  typed while a drained turn runs is untouched.
- =start/end-agent-turn= wrapped in =save-excursion=: a render must never
  park point on the anchor, or the user's next keystroke lands above the
  box.

Tests: =test-agent-org-draft-survives-streaming-renders= pins the
invariant; send/queue/cancel suites re-typed for buffer input.

** DONE Reload --- restart the same session in place
agent-shell's =agent-shell-reload= (agent-shell.el:1604) is exactly
"restart with the same =:session-id=": it kills the chat buffer with its
agent and starts a fresh one through the resume path, reusing the old
windows.  Nothing is re-read from the old transcript — the agent's
history is the source of truth.

Ported as =agent-org-reload=: guards on :loading / missing :session-id,
asks =y-or-n-p= before killing a live turn, then shuts the agent down,
kills the chat buffer silently (the kill hook owns the process) and
re-opens through =agent-org-resume-session= with the recorded
=(:cwd . :session-id)=, replaying into the same windows.  The buffer
name regenerates from the replayed title and id, so it comes back
looking like the one that was replaced; queued prompts die with the
buffer.

** DONE Interrupt --- cancel a running turn
agent-shell binds =agent-shell-interrupt= (agent-shell.el:2243): it
rejects any pending permission requests and sends the fire-and-forget
=session/cancel= notification, leaving the turn to end when the agent
answers.  agent-org answers the same notification, but an agent that
never does would keep the buffer frozen in Streaming forever -- exactly
the state the cancel was for.

Ported as =agent-org-cancel-turn= (bound to C-c C-k in
=agent-org-mode-map=): sends =session/cancel= with the live session id,
then closes the turn locally -- end the heading, =Ready (turn
cancelled)= in the header, live prompt back.  A per-turn id
(=agent-org--send-turn''s =:turn=) makes the agent's late answer to the
cancelled request drop instead of double-closing or double-draining.
The prompt queue is NOT cleared: the cancelled turn was the only thing
holding it, so the queue drains right away.

* Display fixes (the user's live complaints)
** DONE Buffer name carries the project name and session id
agent-shell names buffers ="Claude Agent @ project"= via
=agent-shell-buffer-name-format= and shows the session id separately
(=agent-shell-show-session-id=).

Shipped: =agent-org-buffer--wanted-name= renders
=*agent-org: <project> <title|provider> [sid]*=, the project being the
last directory component of the session cwd (already in the status
model as =:project=).  =agent-org-buffer-create= now applies that name
at creation, so even the handshake buffer reads
"*agent-org: myproj goose*" -- findable by project before the agent
answers.  The sid stays truncated exactly as before; renames still fire
only on =:title=/:session-id= updates plus the equality guard.
Guarded by =test-agent-org-buffer-name-carries-project= and the
updated exact-name tests, which bind =ao--name-dir= so the project
part never depends on where the suite was launched.

** DONE Tool call headings must not show raw ids
agent-shell renders tool calls through =agent-shell-make-tool-call-label=
and never shows the =toolCallId=; agent-org interpolated it into the
visible heading text.

Shipped: the heading line carries only the TODO keyword and the
flattened title (agent-org-buffer.el, =agent-org-buffer-insert-tool=).
The id is still the key of =agent-org-buffer--tools=, so in-place
updates find their heading through the stored marker without the wire
id ever being readable text.  Guarded by
=test-agent-org-tool-heading-drops-raw-id=; the older tool tests now
assert the id-free shape.

** DONE Model name everywhere, not just the header
=:model-name= was preferred by the header and the :Model: property, but
the CONFIG drawer printed the raw =currentValue= id and
=agent-org--model-name= returned nil for an unadvertised current
value.

Shipped: the CONFIG drawer renders each option's current value through
=agent-org-buffer--config-value= -- the advertised label when the
option's own =options= list carries one, the raw id only as the
fallback for a value outside the catalog.  =agent-org--model-name=
never answers nil for a present value: with no label it drops the
provider path from the id ("minimax/MiniMax-M3" becomes "MiniMax-M3").
Guarded by =test-agent-org-config-drawer-shows-model-label= and
=test-agent-org-model-name-prettifies-unadvertised-current=.

** DONE Never touch the mode line
CONVENTIONS.md section 6 already mandates header-line-only status with
=:lighter nil=, and =test-agent-org-leaves-mode-line-alone= guards it.
Keep it that way: doom-modeline owns the mode line; agent-org renders
into the header line only.

** DONE Keep Org colors live while streaming
=agent-org-buffer-start-agent-turn= switched =font-lock-mode= off for the
whole turn (a speed hack) and =end-agent-turn= switched it back, so every
Org color vanished mid-response.  Shipped: streaming never touches
font-lock; only the freshly appended region is fontified, so colors stay
live at negligible cost.  The one bulk path that still needs suppression
is =agent-org--render-replay= (hundreds of synchronous insertions), which
now disables font-lock for the paint run and flushes once at the end.
=test-agent-org-streaming-never-toggles-font-lock= pins the no-toggle
invariant.

** DONE Show the session title in =#+TITLE: for silent agents
Qoder never pushes =session_info_update= (live-verified: a full wire
capture held zero of them), so =#+TITLE:= stayed on the provider-name
fallback forever even though the agent had a title for the conversation.
Shipped: =agent-org--sync-title= asks =session/list= once, after the
first turn ends, matches the row by session id and lands the title.  It
is one-shot (=:title-seeked=), capability-gated so a silent agent is
never asked (=:lists-sessions=, recorded from =initialize=), skipped
when a title already arrived by any route, and :quiet so the echo area
is not stolen.  Four tests in /tests cover fetch, gating, known-title
and one-shot.

** DONE Session id is an Org =:ID: property, not a bar segment
The user first asked for a =#+ID:= keyword line, then corrected it to a
standard Org =:ID: property: a keyword is invented markup, a property is
what Org's own id machinery reads.  Shipped:
=agent-org-buffer--render-metadata= emits =:ID: <session-id>= inside the
top =:PROPERTIES:= drawer (between Provider and Mode) /only/ when the id
is real — =:ID: unknown= would be a fake property and Org's id tooling
would choke on it; and =agent-org-buffer--render-header-line= dropped the
=[sid]= segment, so the bar carries state only.  The buffer name keeps
=[sid]=: two qoder chats otherwise collapse into one entry in =C-x b=.
Qoder's id is a real UUID, so the transcript is now a genuine
=id:=-link target, which feeds the Org-features item.  (Side fix:
=agent-org-buffer--todo-setup= moved above =agent-org-buffer-create= —
using it before the =defconst= byte-compiled as a free variable.)

** DONE Killing a chat buffer asks, because an agent is running
User order: "When killing agent-org buffer, it should ask that a process is
running and should that be killed mirrorring Emacs process buffers."
=acp= spawns the agent with ~:noquery t~ and no process buffer, so Emacs' own
query finds nothing and the kill was silent — on a machine where a stray
=qoder --acp= child costs ~100 MB.  Shipped: =agent-org--kill-query= on
=kill-buffer-query-functions= (buffer-local, installed by
=agent-org--register-session=), asking Emacs' own question — =Process %s is
running; kill it? = — and only for a /live/ child.  The first version read the
client with =plist-get= and so asked nothing at all: acp's client is an /alist/
of dotted keyword pairs, see AI-REVIEW.org.  Verified live against
=goose acp=: NO keeps buffer and agent, YES kills and the kill-hook's
=acp-shutdown= leaves no child.

** DONE A switcher for open chats
User order: "A buffer switcher is needed, too."  Shipped:
=agent-org-switch-buffer= (M-x, agent-shell's name — it binds nothing either,
and =C-x b= already reaches every chat).  Rows are =LABEL  STATUS  [id]= built
by the same column machinery the session chooser uses, ordered as the registry
is (newest chat first), and their value is the BUFFER object rather than a
name an agent can rename.  It found one real bug on the way: two =Qoder= chats
in two projects printed identical rows but for their UUIDs, so the label is now
=agent-org-buffer--chat-label= — the same function the buffer name is built
from, project directory first.  Nine tests in /tests, both column assertions
mutation-checked.

** TODO Model-name turn headings (design settled, no code written)
User order: "Use model name instead of 'Agent' by default. You will have
to maintain a map for each agent response's model in a session for it."
Delivered from the wrong project session (org-docs) on 2026-10-03; the
design below is all that survived the hand-off.

- defcustom =agent-org-use-model-headings= (default t) beside
  =agent-org-use-header-line= in agent-org-buffer.el; nil keeps =* Agent=.
- Heading text comes from the buffer-local status:
  =agent-org-buffer--model-display= (= :model-name, falling back to
  :model), flattened with =agent-org-buffer--label=; nil model → plain
  =* Agent=.  That fallback keeps every existing =\\* Agent= test green,
  because the fixtures' statuses carry no model.
- Exactly one site writes the heading — the =insert "* Agent\n\n"= in
  =agent-org-buffer-start-agent-turn= — every placement goes through
  =agent-org-buffer--turn-anchor=/render-end markers, so the rename is
  safe.  The function already receives SESSION (as =_session=; nil on
  the insert-tool path).
- The map: session key =:turn-models=, an alist (turn-number . model),
  recorded in start-agent-turn from =(plist-get session :turn)=.  It
  MUST be pre-installed in =agent-org--open-session='s key list
  (agent-org.el, next to =:pending-prompts=): =setf= on =plist-get=
  cannot create an absent key.  Add it to the test fixture
  =ao--make-test-session= too.
- Tests first: model known → =* <name>= heading + map entry; no model →
  =* Agent=; option nil → =* Agent= despite a model; two turns with a
  model change → two map entries and the older heading untouched.

** TODO One Org transcript file per session, kept updated
"By default, keep a single Org transcript file to map to a session and
regularly update it."  agent-shell's model: a buffer-local file path and
=write-region ... t 'no-message= appending each chunk — no full rewrite,
so cost is one disk append per update.  Defcustom for on/off and the
directory; the =:ID:= drawer line names the file and makes the
transcript an =id:=-linkable document.  Overhead must be measured on
this 4 GB machine before declaring it cheap (see next item).

** TODO Markdown → Org for user and agent replies (default on, off-able)
agent-shell only renders markdown to /faces/, never to Org, so this is
beyond parity: convert headings, emphasis, lists, fences and tables of
each reply into real Org markup, defcustom-gated.  Keep it a cheap
in-buffer transform on the hot path (no pandoc per chunk).  Per the
user: compute the overhead and report it, asking for a switch if the
cost says so.
