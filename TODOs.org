#+title: agent-org TODOs --- features to port, inspired by agent-shell
#+options: num:t toc:nil

This is the porting list from `agent-shell' (upstream xenodium/agent-shell,
source at ~/agent-shell) onto agent-org's Org-native design.  Each item
names the agent-shell mechanism it comes from and the agent-org functions
it touches.  Everything marked DONE is on this branch with tests in
tests/test-agent-org.el.

* Basic chat-loop features (this round)
** DONE Prompt queue --- submit while the agent is still responding
agent-shell keeps this in =agent-shell-prompt-queue.el=: the queue lives
in the session state under =:pending-prompts=; =agent-shell--prompt-queue-enqueue=
stores a prompt typed while busy, and =--process-next= auto-drains it
when the turn ends.  Commands: =agent-shell-prompt-queue= (view),
=-resume=, =-remove=; a defcustom picks the busy-submit policy
(queue vs error).

Ported to agent-org as:
- Session key =:pending-prompts= (FIFO list of strings).
- =agent-org-send= enqueues instead of signalling "Agent is still
  responding" while =:streaming=; option =agent-org-queue-when-busy=
  keeps the old hard-error behaviour when nil.
- Drain only on a *successful* turn end (=agent-org--drain-queue= called
  from the send success callback); a failed turn leaves the queue intact
  so nothing hammers a dead agent.
- =agent-org-queue-view= (transient listing), =agent-org-queue-remove=
  (drop one, completion), =agent-org-queue-edit= (pull the last queued
  prompt back into the minibuffer prompt read).
  /Superseded:/ [[*The queue editor: edit and re-order the waiting prompts]].
  All three of those commands are gone; one =agent-org-queue-edit= is now a
  real editor, not a minibuffer pull.
- Header status shows the pending count while busy (convention: header
  line only, never the body, never the mode line).

*** DONE Queue input comes from the buffer, not the minibuffer
The first port read queue input with =read-string=, because sending froze
the live =* User= heading and left nowhere to type mid-turn.  That is not
agent-shell's model: =agent-shell-persistent-prompt-enabled= keeps a
writable prompt at the buffer end /through/ the turn, so queueing is just
submitting into a busy shell.

Ported as the persistent type-ahead box:
- =agent-org-buffer-insert-prompt= opens one =* User= box and sending
  never consumes it; every turn boundary can call it and the open box
  makes it a no-op.
- =agent-org-buffer--prompt-anchor=: a rear-advancing marker at the box's
  leading separator.  Rear-advancing is the whole trick -- text inserted
  at the anchor position pushes the marker (and the box) down, so renders
  keep arriving above it in order instead of stacking in reverse.
- =agent-org-buffer--render-end=: anchor position, or =point-max= when no
  box exists (a replay).  Every per-turn render site -- user echo, agent
  heading, chunks, :tool: drawer, :thinking: drawer -- inserts there
  instead of =point-max=, so a streaming response never scribbles over a
  fresh draft.
- =agent-org-buffer-take-draft= replaces =agent-org-buffer-read-prompt=:
  read + clear the box, keep it open; a blank draft errors and leaves the
  typed text in place.
- =agent-org-send= is now one gesture: idle sends the draft (frozen echo
  above the box, turn on the wire), streaming queues it.  No minibuffer
  for new prompts; =agent-org-queue-edit= used one then too (the entry has
  left the input area) --- it is a buffer now, see
  [[*The queue editor: edit and re-order the waiting prompts]].
- Drained prompts render as frozen echoes above the box, and a draft
  typed while a drained turn runs is untouched.
- =start/end-agent-turn= wrapped in =save-excursion=: a render must never
  park point on the anchor, or the user's next keystroke lands above the
  box.

Tests: =test-agent-org-draft-survives-streaming-renders= pins the
invariant; send/queue/cancel suites re-typed for buffer input.

** DONE Reload --- restart the same session in place
agent-shell's =agent-shell-reload= (agent-shell.el:1604) is exactly
"restart with the same =:session-id=": it kills the chat buffer with its
agent and starts a fresh one through the resume path, reusing the old
windows.  Nothing is re-read from the old transcript — the agent's
history is the source of truth.

Ported as =agent-org-reload=: guards on :loading / missing :session-id,
asks =y-or-n-p= before killing a live turn, then shuts the agent down,
kills the chat buffer silently (the kill hook owns the process) and
re-opens through =agent-org-resume-session= with the recorded
=(:cwd . :session-id)=, replaying into the same windows.  The buffer
name regenerates from the replayed title and id, so it comes back
looking like the one that was replaced.  Queued prompts used to die with
the buffer; they now survive in the transcript's =:QUEUE:= drawer (see
[[*Persist the prompt queue, and reload it on resume]]), so a restart hands
them to the fresh agent.

** DONE Interrupt --- cancel a running turn
agent-shell binds =agent-shell-interrupt= (agent-shell.el:2243): it
rejects any pending permission requests and sends the fire-and-forget
=session/cancel= notification, leaving the turn to end when the agent
answers.  agent-org answers the same notification, but an agent that
never does would keep the buffer frozen in Streaming forever -- exactly
the state the cancel was for.

Ported as =agent-org-cancel-turn= (bound to C-c C-k in
=agent-org-mode-map=): sends =session/cancel= with the live session id,
then closes the turn locally -- end the heading, =Ready (turn
cancelled)= in the header, live prompt back.  A per-turn id
(=agent-org--send-turn''s =:turn=) makes the agent's late answer to the
cancelled request drop instead of double-closing or double-draining.
The prompt queue is NOT cleared: the cancelled turn was the only thing
holding it, so the queue drains right away.

** DONE Show what a tool call printed, in agent-shell's activity order
#+begin_quote
"Show tool call outputs, too.  Please look into agent-shell on how it
handles responses."  "Keep activity order just like agent-shell handles

** DONE One Org transcript file per session, kept updated
"By default, keep a single Org transcript file to map to a session and
regularly update it."  agent-shell's model: a buffer-local file path and
=write-region ... t 'no-message= appending each chunk — no full rewrite,
so cost is one disk append per update.  Defcustom for on/off and the
directory; the =:ID:= drawer line names the file and makes the
transcript an =id:=-linkable document.  Overhead must be measured on
this 4 GB machine before declaring it cheap (see next item).

Shipped, but NOT as an append log: the file is a MIRROR of the buffer's
frozen body (=point-min= to =agent-org-buffer--render-end=) rewritten at
turn boundaries.  An append log cannot hold agent-org's tool calls —
one =:tool:= drawer line rewritten TODO→DOING→DONE — without keeping every superseded
state of every call, and it would be a second renderer (CONVENTIONS.md
§9: never add one).  Mirror also means the unsent draft is excluded by
the same marker that protects it from a streaming turn.

- =agent-org-transcribe= (default t) and =agent-org-transcript-directory=
  (default the RELATIVE =.agent-org=, resolved against the chat buffer's
  =default-directory= — so each project keeps its own transcripts; an
  absolute setting is one global pool), created on the first write.
- One file per session, named =<id>.org= by
  =agent-org-buffer--transcript-name=, which replaces every character
  outside =[A-Za-z0-9._-]= with a dash: the id comes off the wire and
  becomes a path, so =../../etc/passwd= must not be a file name the agent
  chose.  The =:ID:= property the metadata block already writes makes it
  an =id:=-linkable document, exactly as this item asked.
- Boundaries: =agent-org--session-ready= (so a restored session is on disk
  with no prompt sent), =agent-org--send-turn= before the request and in
  both callbacks, =agent-org-cancel-turn=, =agent-org--sync-title= and
  =agent-org--forget-session= — a kill is not a turn boundary and the turn
  in flight has no end coming, so without that last one the final answer
  of every chat is the one missing from the file.
- =agent-org-buffer--transcript-cache= skips a body that has not changed,
  so a repeated title or a second Ready touches no disk and leaves the
  file's mtime honest.
- A =file-error= is a =message= in the echo area, never a broken turn;
  =write-region='s VISIT stays nil or the chat buffer would start
  /visiting/ its own transcript and =C-x s= would save the draft into it.

Overhead, measured on this machine (spinning =sda=, 4 GB, =emacs -Q
--batch=, one whole-file write per boundary): 3 ms for a short chat, 6 ms
at 20 turns (21 KB), 9 ms at 50 turns (103 KB), 15 ms at 100 turns
(407 KB); an unchanged body is skipped in 0.02–3.4 ms.  Two boundaries per
turn, twenty chunks of an answer cost nothing — versus 90–170 ms per turn
for the per-chunk append model, spent inside the stream.  Twelve tests
=file-is-named…= through =flushes-when-the-buffer-is-killed=; they are the
suite's first to touch a filesystem, so =tests/test-agent-org.el= now
requires =ert-x= for =ert-with-temp-directory=.

** DONE Persist the prompt queue, and reload it on resume
User order: "Save queued prompts to transcripts and reload them on
resume."  Nothing else in the package can do this: a queued prompt was
never sent, so it is absent from the agent's =session/load= replay, from
the fresh buffer and from any =* User= heading — the transcript is its only
surviving copy.  It goes in a =:QUEUE:= drawer at the end of the
auto-managed metadata block (folded as first built; it arrives open now, and
is uncapped — see [[*The queue editor: edit and re-order the waiting prompts]]),
one line per prompt oldest first, escaped flat
by =agent-org-buffer--queue-encode= (a drawer cannot hold a blank line, and
a prompt that /is/ =:END:= must not close its own drawer — hence the =- =
prefix).  =agent-org--queue-refresh= is the single choke point: it mirrors
session =:pending-prompts= into the status, the block and the file, so
every queue mutation --- enqueue, drain, and the editor's apply --- is a
boundary of its own and a mid-turn
quit costs nothing.

=agent-org--finish-replay= reads the drawer /before/ rendering and applies it
/after/ =agent-org--session-ready=, and both halves of that order are
load-bearing: session-ready mirrors the freshly replayed buffer — which has
no queue — over the file.  Applying it late is what lets the queue /drain/:
a resumed session is idle, and nothing but a turn end drains an idle
session's queue, so the first prompt goes out and the rest keep waiting.  An
empty queue renders no drawer at all, which is what stops a sent prompt being
restored a second time.

Eight tests: the pure renderer, the escape round-trip (=:END:=, newlines,
backslashes, the empty string), the fold, the mid-turn file write plus its
read-back, the clearing on drain, the resume that restores and sends, and two
negatives (no drawer, no file) — because a phantom turn would spend tokens
the user never asked for.

** DONE Markdown → Org for user and agent replies (default on, off-able)
agent-shell only renders markdown to /faces/, never to Org, so this was
beyond parity: ~agent-org-convert-markdown~ (default on) turns a reply's
headings, emphasis, star bullets, fences, dividers and table rules into
real Org markup, and the user's own echoed prompt with the same rules —
the agent still receives the markdown as typed, so it is rendering, not
translation (CONVENTIONS.md §15).  A heading shifts /one level down/
because level 1 belongs to the conversation; an unclosed fence is closed,
because an open ~#+begin_src~ would swallow the buffer and the transcript.

Overhead, computed as asked: ~110 µs per markup-dense line, ~17 µs per
plain line, printed by ~test-agent-org-markdown-conversion-cost-per-line~.
A 50-line answer is ~2 ms once; a 2000-line replay ~230 ms inside the pass
that replay already is.  That is the same order as a transcript boundary
write (§14), so the switch ships ON and no cost-based ask is needed — the
escape hatch is there for preference, not for price.

The streaming design changed on the way: holding the unfinished line until
its newline (the first cut) made a one-line reply — which usually never
sends a newline — invisible until the turn ended.  Now every chunk is
written and the last line is provisional, rewritten in place by the next
one, frozen at each boundary that draws a drawer below the turn's text.
Fifteen tests, including the two bugs that design caught: a helper's
~string-match~ clobbering the scan's global match data (an infinite loop,
found by the cost probe rather than a hang report), and a detached marker
that still answers ~markerp~ (the chunk after one ending in a newline
crashed on ~goto-char~).

** DONE Org colours: a chat buffer gets them at display time, and keeps them
User report, second occurrence: "colors gone again!"  The root fact, measured
in the live Emacs rather than assumed: ~font-lock-mode~ cannot be *enabled* in a
buffer no window is showing — ~(font-lock-mode 1)~ there leaves the
buffer-local variable ~nil~ with no error and no trace, and ~turn-on-font-lock~
does the same, while in a displayed buffer it sticks.

Two consequences, both now pinned:
- The replay's "suppress font-lock for the bulk paint, restore it afterwards"
  was a one-way door: the ~OFF~ works anywhere, the ~ON~ does not, so a resume
  that painted into a background chat — the ordinary case — removed the
  colours permanently.  The suppression is gone; ~agent-org--render-replay~
  only ~font-lock-flush~es, inside the ~unwind-protect~ that stops the
  progress report (CONVENTIONS.md §9).
- A chat buffer is created inside an acp callback, hence always hidden, so
  ambient ~global-font-lock-mode~ can never reach it.  ~agent-org-mode~ now adds
  ~agent-org-buffer--ensure-font-lock~ to the *buffer-local*
  ~window-configuration-change-hook~, which Emacs runs with the buffer current
  the first time a window shows it (§16).

Two tests replace the one that lied: ~…-replay-restores-font-lock-when-the-paint-errors~
asserted a *restore*, which only batch Emacs can even simulate, so it pinned the
very behaviour that destroys the colours live.  In its place

** TODO Hooks on the response boundary, and automation that answers the agent

** Design guardrails every idea below must respect
- Never call =org-clock-in=/=-out=/=-load= or set an =org-clock-*= variable, and
  only ever write a /closed/ =CLOCK:= range — reporting reads that data; nothing
  here may occupy Org's one global running-clock slot (§22).
- The transcript is a mirror of point-min..=--render-end= written at boundaries —
  an archive/refile/export move must stay above the render end or be excluded,
  and must not disturb the auto-managed metadata block or the turn markers.
- Queue NEXT/WAIT are DERIVED from position and reconciled BY TEXT on apply — any
  dependency/TODO-cycling idea drives =:pending-prompts=, never a TODO state-change
  hook owning dispatch (§17, §20).
- This is a 4 GB Celeron: prefer ON-DEMAND dynamic blocks, columns, agenda and
  event-driven hooks over timers or whole-buffer repaints; none of these ideas
  should add per-chunk cost.

** Reporting over the clocks/cost we already write  (highest value, lowest cost)
- =#+begin: clocktable :scope file :maxlevel 1= on a transcript, or a project-wide
  one, sums every exchange's closed =CLOCK:= into response time per day and per
  =:author:= model — a free read of data we already file.  Add =:properties
  ("COST" ...)= for a seconds-AND-dollars-per-model table.
  (doc.org §org-clock-report =C-c C-x C-r=, §org-clocktable-write-default;
  orgcard.org "Clocking time")
- A =#+COLUMNS:= line in the metadata block turns the buffer into an editable
  spreadsheet of exchanges (ITEM/RESPONSE/COST/MODEL/PROVIDER), =org-columns-edit-value=
  to stamp one value across many turns — quick triage of slow/expensive exchanges.
  (doc.org §org-columns, §org-columns-edit-value)
- A native propview-style roll-up (org-collector) filtering exchanges by arbitrary
  elisp over their properties (e.g. =(string= MODEL "...")=), which clocktable
  cannot do for non-time properties.  (org-collector.org :id/:conds/:cols)
- Scope the current project's =.agent-org/= dir as =org-agenda-files= for a
  clockreport across all a repo's sessions.  Ship it with =org-agenda-inhibit-startup t=
  and capped file sets so it doesn't stall the Celeron.  (agenda-optimization.org;
  doc.org §org-agenda-clockreport-parameter-plist)
- An =:EFFORT:= budget on a prompt (org =C-c C-x e=) compared against the closed
  =:RESPONSE:=, so an unexpectedly slow turn is flagged.  WARNING: wire the
  overrun face off the CLOSED clock/property, never off running-clock state.
  (doc.org §org-set-effort, §org-effort-durations)

** Executing and applying the agent's code (babel)
- =C-c C-c= on a =#+begin_src= inside a quote runs it with =org-babel-execute-src-block=
  and writes =#+RESULTS:= between =--quote-end= and =--render-end= (never the User
  box) — a "does this work?" loop on the spot.
  (org-contrib/babel/intro.org "Executing Code Blocks"; org-eval-light.org)
- Inject =:eval query= (or =:eval never=) at fence→src conversion so agent code is
  UNTRUSTED by construction: the first run of each block prompts to confirm.  This
  is the safety spine for every eval idea here.  (org-contrib/babel/header-args.org :eval row)
- =agent-org-tangle-review=: an agent emits =:tangle path=, we run
  =org-babel-tangle= on just that exchange into a TEMP path, show a diff, and ask
  before touching the working tree — "here's the updated function" becomes an
  apply-this-edit affordance, gated because it writes real files.
  (org-contrib/babel/intro.org "Literate Programming"; header-args.org :tangle)
- A per-chat named =:session= (seeded from the sid) so a variable defined in one
  exchange's block is visible to the next — multi-turn prototyping keeps state.

- Loop a block's =:results output= (test stdout, a file read) back into the NEXT

  (intro.org "Using an Org Table as Input"; library-of-babel.org =read=/=extract-lines=)
