* Data-flow correction (v1.3 — Owner 2026-11-04 #hq)

"Why do you even need a CHAT.org renderer?  It's supposed to be
auto-saved from team chat buffer to CHAT.org."
Binding; the data flow is now stated as law:

- The LIVE team chat buffer (U4 region, §10.4) is the only
  interactive chat surface.  Its auto-save APPENDS to CHAT.org —
  the file is the log, never a second UI, and U1 never runs while
  a live session exists.
- U1 is the reopen/resume READER of that log, needed only for the
  moments the live buffer does not exist: after a restart or crash
  (the buffer dies with Emacs, the file survives), to see entries
  other seats appended from CI or other machines while this Emacs
  was closed, and for history inspection.  Without it the
  auto-saved archive is write-only.
- Command renamed =agent-team-chat-render= → =agent-team-chat-open=:
  when a live team chat session EXISTS it switches to that buffer
  (never forks state); only when none exists does it build
  =*agent-team Chat*= from the file.  The file stays the single
  source of truth (§11.3 unchanged).
- Everything else is untouched by v1.3: kit law (MSG→§4 mapping,
  derived =:MSG-ID:=, =chat-member:= / =chat-msg:= links), faces,
  verbs, hygiene and the ERT fixture plan stand as written.

** Buffer and naming (§2)

- Command =agent-team-chat-open= opens =*agent-team Chat*= (§2
  naming under the =agent-team-= prefix per §10.1; v1.2 correction,
  renamed from =agent-team-chat-render= by v1.3 — open resolves to
  the live buffer when one exists, per * Data-flow correction).
- One level-1 heading =* Team chat= with drawer
  =:CHAT-ID: agent-team/CHAT.org= / =:KIND: group=; =#+STARTUP: overview=
  at buffer top (§4 sample).
- When it builds from the file (no live session), the buffer RENDERS
  the file and the file is the single source of truth (§11.3 — no
  parallel chat state may exist; v1.3: during a live session this
  buffer must not exist at all — the U4 region is the surface).
  Rebuild = kill and rebuild the buffer (same decision as
  emacs-purple 0882373: fresh buffer = fresh Org element cache and
  fold registry).

** MSG → §4 mapping (§10.2; CHAT.org format law unchanged)

| CHAT.org source                            | rendered                                  |
|--------------------------------------------+-------------------------------------------|
| =* MSG <from> -> @<to> :<kind>:=              | =** [<WHEN>] <from> -> [[chat-member:…][@<to>]] :<kind>:= |
| =:FROM:=                                   | =:AUTHOR:= property                       |
| =:TO:=                                     | =:TO:= property + =@target= in heading text |
| =:KIND:=                                   | tag on the message heading                |
| =:WHEN:= =[YYYY-MM-DD Day HH:MM UTC]=      | inactive stamp =[YYYY-MM-DD Day HH:MM]=; zone kept in =:WHEN-ZONE:= property |
| =:CHANNEL:=                                | =:CHANNEL:= property (§5 addition)        |
| indented body text                         | message body paragraphs (blank-line split); URLs → =[[url]]=; =@mentions= → =chat-member:= links |

- Derived =:MSG-ID:= law: CHAT.org is append-only and union-merged, so
  ids MUST be derivable without mutating the file.  MSG-ID =
  =msg-<first 8 hex of sha1(FROM "\0" WHEN "\0" first 80 body chars)>=,
  written only into the RENDER buffer's =:PROPERTIES: drawers; legacy
  entries missing =:WHEN:= degrade to a positional id (documented,
  links to them are best-effort).

** Links (§10.3)

- =[[chat-member:PROVIDER/MODEL@PLATFORM][@name]]= — FROM/TO/@mention
  handles map through MEMBERS.org where known; unknown handles degrade
  to plain =@name= text (never break the render).
- =[[chat-msg:MSG-ID][↩ first words]]= — resolution via the derived-id
  law; explicit reply-line linkification lands in U2 (U1 renders the
  prose form unchanged).
- =:tool:= / =:thinking:= drawers in bodies pass through unchanged and
  keep Org's native folding (§10.3).

** Faces / tags / verbs / hygiene (U2 direction, recorded here)

- Faces: =agent-team-chat-*-face= mirrors the §6 role table (unread,
  mention, preview, time, current) — five deffaces, defgroup above
  them (audit/01 ordering hygiene).
- Tags: =:KIND:= passes through (=:dispatch:=, =:escalation:=, …);
  =:queued:= / =:err:= arrive with U3; numeric unread pairs do NOT
  apply to the transcript (append-only archive) — documented
  deviation from §5, not a violation.
- Verbs: =g= re-render from file, =q= bury (never lock the file —
  other seats append from CI), =TAB= native cycling, narrowing native
  (§7); =RET= on a =chat-member:= link opens/starts that member's
  session/dispatch through agent-team.el's own member path — U2, with
  the U3 MEMBERS registry as the transport source of truth.
- Hygiene (§8): =buffer-disable-undo= on the render buffer, read-only
  buffer, all inserted file strings pass through
  =substring-no-properties=, =q= buries, killing the buffer never
  touches the file.

** A. Transcript viewer half (agent-team.el, agent-team-chat.el)

A1. Faces (§6 role table under the §10.1 prefix law): five deffaces
=agent-team-chat-unread-face= (inherit =org-warning=),
=agent-team-chat-mention-face= (=bold=),
=agent-team-chat-preview-face= (=shadow=),
=agent-team-chat-time-face= (=org-date=),
=agent-team-chat-current-face= (=highlight=), under a new
defgroup =agent-team-chat= placed above them (audit/01 ordering
hygiene).  Faces ride FONT-LOCK keywords in
=agent-team-chat-archive-mode= — never text properties — so the
zero-text-property render law (U1 ERT) stands untouched:
- mention -> =@handle= tokens in body lines;
- preview -> message body lines (the scannable-preview role);
- current -> the level-1 =* Team chat= title (the open conversation's
  name role);
- time -> delivered by Org's native timestamp fontification (the kit
  face inherits =org-date= — same law, no keyword fights Org);
- unread -> defined for kit completeness; an append-only archive has
  no read state, so no anchor applies it (documented deviation, same
  law as the numeric-pair deviation).  The U4 live region applies it.

A2. Verbs (§7 view column):
- =j= -> =agent-team-chat-jump-latest=: point to the newest (last)
  message heading — the archive degradation of jump-to-first-unread
  (no read state; every chat client resumes at the tail).
- =RET= -> native Org link opening.  Two new link types via
  =org-link-set-parameters= (top-level, idempotent):
  =chat-member:= follow -> =agent-team-chat-visit-member= locates the
  =* <Role> — <id>= heading in MEMBERS.org and pops to it (the
  member's registry entry — agent-team.el's own member path today);
  unknown id = user-error naming the handle, never silent.
  =chat-msg:= follow -> =agent-team-chat-goto-msg= resolves the
  derived =:MSG-ID:= in the render buffer and jumps to its heading;
  from any other buffer it opens the archive first, then jumps; not
  found = user-error naming the id.  Transport-aware dispatch waits
  for the U3 registry (:TRANSPORT:), documented.
- =C-c C-c= send-draft: N-A in the archive (v1.3: the reader never
  writes the file; drafts live on the U4 live surface) — documented
  deviation, not an omission.
- =g= / =q= exist since U1.

A3. Touch adaptation (§7 parity): defcustom
=agent-team-chat-adapt-for-touch= (default t), predicate
=agent-team-chat--touch-device-p= (the kit's three signals:
system-type android, TERMUX_VERSION env, touch-screen terminal
parameter), and =agent-team-chat-touch-mode= minor mode bound when
the archive buffer is built on a touch device: single tap = RET on
the current line, =scroll-conservatively= 101, =truncate-lines= t —
the emacs-purple kit pattern verbatim.

A4. Hygiene (§8): U1 landed undo-disable, read-only,
substring-no-properties, bury; U2 adds the ERT assertions
(buffer-undo-list eq t; buffer-read-only t) so the law is pinned.

A5. ERT additions (offline, deterministic): five faces defined with
the §6 inheritance; font-lock in the render buffer puts
=agent-team-chat-mention-face= on an @handle body token,
=agent-team-chat-preview-face= on a body line,
=agent-team-chat-current-face= on the =* Team chat= title (assert
AFTER =font-lock-ensure= on the BUFFER — the zero-property assertion
stays on the RENDER STRING; the two never conflate); =j= lands on the
last message heading; chat-member follow resolves the fixture id and
user-errors on an unknown one; chat-msg follow resolves a derived id
inside the render buffer; touch predicate responds to the terminal
touch-screen parameter (set-terminal-parameter in the test, restored).

** B. Solo-ACP session-buffer half (agent-org, agent-org-buffer.el)

B1. Faces: five deffaces =agent-org-chat-unread-face=, …-mention-,
…-preview-, …-time-, …-current-face (same §6 inheritance) under
defgroup =agent-org-chat=.  Solo sessions exercise current (the open
session's name) and time (Org-native stamps); unread/mention/preview
are group/list roles (§5 numeric pairs) — defined, documented, not
applied (same deviation law as A1).

B2. Application: font-lock keyword in =agent-org-mode= putting
=agent-org-chat-current-face= on the session's =#+TITLE:= line (the
open chat's name role).

B3. Verbs: =q= -> bury-buffer (§7 quit) added inside
=agent-org-buffer--build-mode-map= (the fill-not-replace law keeps
hot reloads live).  =C-c C-c= already is the §7 send-draft verb; the
rest of the §7 table is list/view law (N-A solo).

B4. Hygiene (§8): the two backend entry points
=agent-org-buffer--append-part-stream= and the part-body replace path
wrap incoming wire TEXT in =substring-no-properties= — backend text
properties never reach Org's fontification.

B5. ERT additions in tests/test-agent-org.el: faces exist with §6
inheritance; =q= is bound to bury in =agent-org-mode-map=; the
#+TITLE keyword applies the current face; a property-laden stream
chunk lands property-free.
